Du bist Lead Software Architect, Senior Full-Stack-Entwickler, Multiplayer-Backend-Entwickler und UI/UX-Designer.

Entwickle ein vollständiges webbasiertes Multiplayer-Partyspiel, das vom Spielprinzip moderner Meme-Partyspiele inspiriert ist.

Es darf jedoch weder Markenname, Quellcode, Grafiken, Meme-Sammlungen, Texte noch das konkrete UI eines existierenden Spiels kopieren.

Das Produkt soll eine eigenständige Plattform mit eigener Identität, eigenem Design und deutlich flexiblerer technischer Architektur werden.

# PRODUKTZIEL

Baue ein Browsergame, bei dem mehrere Spieler gemeinsam einer Lobby beitreten und in mehreren Runden kreative Inhalte erstellen und anschließend gegenseitig bewerten.

Der erste Hauptspielmodus ist ein Meme-Spiel.

Ein Spieler erhält eine Meme-Vorlage und erstellt innerhalb eines Zeitlimits eine Caption.

Nach Ablauf der Erstellungsphase werden alle eingereichten Memes nacheinander oder gleichzeitig präsentiert.

Die Spieler bewerten die Einsendungen.

Danach werden Punkte berechnet.

Nach mehreren Runden gewinnt der Spieler mit der höchsten Gesamtpunktzahl.

Das System darf jedoch NICHT speziell nur für Memes entwickelt werden.

Die zugrunde liegende Game Engine muss so abstrahiert werden, dass später ohne grundlegende Änderungen weitere Partyspiel-Modi implementiert werden können.

Beispiele:

Same Meme

# GAME ENGINE

Die zentrale Game Engine darf nichts über Memes wissen.

Implementiere eine allgemeine serverseitige State Machine.

Jede Phase besitzt:

Der Server ist immer authoritative.

Der Client darf niemals selbst entscheiden, dass eine Phase beendet wurde.

Timer werden ausschließlich vom Server kontrolliert.

Der Client erhält:

und berechnet daraus nur die visuelle Timeranzeige.

# ERGEBNIS

Das Projekt soll kein einfacher Demo-Klon sein.

Es soll eine langfristig wartbare Multiplayer-Plattform entstehen, auf der später viele kreative Partyspiele laufen können.

Prioritäten:

1. zuverlässiger Multiplayer
2. saubere server-authoritative Game Engine
3. Reconnect
4. gute mobile Bedienung
5. modulare GameModes
6. schnelle Ladezeiten
7. einfache Erweiterbarkeit
8. sichere Uploads
9. gute Moderation
10. horizontale Skalierbarkeit.

Wenn eine Architekturentscheidung zwischen schneller kurzfristiger Umsetzung und langfristig sauberer Modularität getroffen werden muss, bevorzuge die saubere Modularität, solange dadurch der erste spielbare Vertical Slice nicht unnötig kompliziert wird.

Arbeite selbstständig weiter, solange keine Entscheidung erforderlich ist, die das grundlegende Produktziel verändert.

Bei kleineren technischen Entscheidungen wähle selbst eine sinnvolle Lösung und dokumentiere sie, statt die Entwicklung zu unterbrechen.
